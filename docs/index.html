Detection heuristics

Prioritize signal over volume. These filters are encoded in the scanner Action.

  • Admission language in descriptions: public screenshots for private-repo PRs, screenshots linked from private repo, camo-renderable, anonymous-resolvable, temporary/ephemeral public hosting, safe to delete after merge
  • Agent footprints: agent-factory, agent-uploaded, cloud agents evidence hosts; commit messages about creating a public screenshot repo / orphan-branch workaround
  • Code/skills that teach agents to upload PR screenshots to a public repo (attach-screenshot skills, Agents.md notes)
  • Tree content: image/media files or PR-number folders (pr-123/, screenshots/) — not README-only
  • Quality gate (excludes noise): empty gitshot-images shells (size≈0, README only) are dropped even if a _gitshot release tag exists — those mass templates are not useful radar hits
  • Name patterns like pr-assets, pr-screenshots, pr-evidence only kept when the repo has real content

How the scanner works

  1. GitHub Action runs hourly (cron: '14 * * * *') + on demand.
  2. Searches repos + commits + code for PixelLeak-class admissions and agent footprints.
  3. Quality-probes each candidate (tree files, size, releases) — drops empty gitshot shells.
  4. Keeps admission-language / named media dumps only; writes docs/data/hits.json when changed.

Quality over quantity. Prefer ~20 real oddities over hundreds of empty templates.
