Detection heuristics

Prioritize signal over volume. These filters are encoded in the scanner Action.

  • name/desc mentions: gitshot, pr-assets, screenshots, demo-assets, agent-assets, before-after, ui-preview
  • Topics/tags including _gitshot
  • New public repos that are mostly image/video assets (png/jpg/webp/mp4) with little/no code
  • Repos created minutes after a private PR workflow that reference screenshot hosting
  • Brand-new empty-ish repos that suddenly get dozens of image commits
  • Description patterns: "assets for PR", "code review screenshots", "temporary image host", "Managed by gitshot", "Ephemeral PR screenshot"
  • Forks of gitshot or tools that upload review screenshots publicly

How the scanner works

  1. GitHub Action runs hourly (cron: '14 * * * *') + on demand.
  2. Queries GitHub Search API for high-signal name/description patterns (recent created:> window).
  3. Merges unique new hits into docs/data/hits.json (idempotent — no commit if unchanged).
  4. This Pages site reads the JSON and renders the live table.

Rate-limited by Search API. Heuristics are intentionally narrow to avoid noise.
